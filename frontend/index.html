    The 9 Data Engineering Responsibilities (Slide 07)

    Every stage from raw ingestion to dashboard reporting is managed by data engineering:

    1. Data Ingestion:

    Collecting operational students and sales transactions into warehouse landing zones.

    2. Data Modeling:

    Designing analytical star-schemas, dimensions, and normalized fact tables.

    3. Data Transformation:

    Cleaning, deduping, and calculating gross amounts, discounts, and return flags.

    4. Data Quality:

    Ensuring valid ranges for student marks, semester limits, and sales figures.

    5. Analytical Storage:

    Structuring columnar tables and indexes for high-throughput aggregation queries.

    6. Semantic Modeling:

    One approved metric definition for Revenue and Academic performance (Slide 05).

    7. Query Optimization:

    Using EXPLAIN QUERY PLAN to detect quadratic Cartesian cross-joins and unindexed scans.

    8. Governance:

    Role-based access control preventing unauthorized users from querying sales facts.

    9. Monitoring:

    Audit logging all query attempts, estimated costs, and ALLOW/BLOCK policy decisions.

    Capstone Presentation Walkthrough

    Overview of the 10 slides from the official project presentation deck.

    10 Slides Deck
    SLIDE 02: THE PROBLEM STATEMENT Problem

    Excessive Governance vs Uncontrolled Query Costs

    Problem 1: Excessive Governance: Too much restriction forces legitimate business users to depend on data engineers for every simple question.

    Problem 2: Uncontrolled Costs: Too much freedom lets unoptimized queries scan terabytes of warehouse data, causing cloud bill shock.

    SLIDE 03: REAL-WORLD EXAMPLE Walkthrough

    University Administrator Scenario

    User Question: "Show average CSE student marks by semester."

    1. ALLOW: Cost is $0.20 ≤ $1.00 budget → runs immediately.

    2. WARN / BLOCK: Cost is $15 > $1.00 budget → flagged/blocked by policy.

    3. BLOCK: Sensitive data (sales) for viewer → blocked regardless of cost.

    SLIDE 05: REUSABLE SEMANTIC LAYER Core Metric

    Single Approved Business Metric Definitions

    Prevents different departments from calculating numbers differently:

    Revenue = Sales Amount − Discounts − Returns

    Benefits: Consistent metrics, reduced ambiguity, reusable definitions, reliable analytics.

    SLIDE 06: COST ESTIMATION & CONTROL Differentiator

    Pre-Execution Resource & Budget Capping

    The platform inspects query plans and estimates resource usage BEFORE executing:

    • Query Plan & Cost Analysis → Estimated Compute ($)
    • Configurable Soft Budget ($0.50) & Hard Budget ($1.00)
    • Policy Engine Decides: ALLOW / WARN / BLOCK
    SLIDE 09: EVALUATION & EXPECTED OUTCOMES Outcomes

    Controlled Self-Service Analytics

    • Reduces unnecessary expensive queries before they consume cloud resources.
    • Ensures semantic metric consistency across users.
    • Enforces governance without blocking legitimate self-service inquiries.
    • Full audit logging and visibility into warehouse usage.
    SLIDE 10: CONCLUSION & FUTURE SCOPE Future Scope

    Next-Generation Roadmap

    • Cloud Data Warehouse integrations (BigQuery, Snowflake).
    • AI-assisted natural language to SQL semantic translation.
    • Automated query rewrite and index recommendations.
    • Advanced lineage visualization and automated budget optimization.
